# AI-ассистент Адыгейского государственного университета

Интеллектуальный чат-бот, реализующий архитектуру RAG (Retrieval-Augmented Generation). Система предназначена для обработки текстовых запросов пользователей и генерации ответов на основе базы знаний, состоящей из официальных PDF-документов и регламентов университета.

## Архитектура системы

Система имеет распределенную микросервисную архитектуру, состоящую из следующих компонентов:

- **Frontend (HTML/CSS/JS)**: Адаптивный пользовательский интерфейс чата с историей диалогов и административная панель для управления базой знаний.
- **Node.js Backend (Express)**: Главный сервер приложения. Отвечает за маршрутизацию HTTP-запросов, стриминг ответов клиенту, управление файловой системой и взаимодействие с внешними сервисами.
- **Python Microservice (Flask)**: Сервис для работы с векторной базой данных. Выполняет парсинг PDF-документов в Markdown, разбиение текста на фрагменты (чанкинг), генерацию векторных эмбеддингов и семантический поиск.
- **Qdrant**: Векторная база данных для хранения эмбеддингов и выполнения поиска по косинусному сходству.
- **llama.cpp**: Локальный сервер языковой модели (LLM) для генерации финального текста ответа на основе предоставленного контекста.

## Принцип работы

1. Пользователь отправляет текстовый вопрос через интерфейс чата.
2. Node.js сервер принимает запрос и отправляет его в Python микросервис.
3. Микросервис преобразует текст вопроса в векторное представление и выполняет поиск наиболее релевантных текстовых фрагментов в базе Qdrant.
4. Найденные фрагменты формируют контекст, который передается в системный промпт для языковой модели.
5. Языковая модель генерирует ответ, строго опираясь на предоставленный контекст.
6. Сгенерированный текст возвращается на фронтенд с эффектом посимвольного вывода (стриминга) и метаданными об источнике (имя файла и URL).

## Функциональные возможности

### Пользовательский интерфейс
- Ввод текстовых запросов и получение ответов в формате Markdown.
- Отображение ссылок на исходные документы, из которых была извлечена информация.
- Сохранение истории диалогов в локальном хранилище браузера (localStorage).
- Использование предустановленных примеров вопросов.

### Административная панель
- Парсинг указанных URL-адресов для автоматического скачивания PDF-документов.
- Просмотр списка и статистики загруженных в хранилище файлов.
- Массовая индексация PDF-документов в векторную базу Qdrant с отображением прогресса в реальном времени через Server-Sent Events (SSE).
- Очистка локального хранилища файлов и векторных коллекций.
- Настройка путей сохранения данных и имен коллекций.

## API Эндпоинты

### Пользовательские методы (Node.js)
- `POST /api/llama-question`: Отправка вопроса и получение полного JSON-ответа.
- `POST /api/llama-question-stream`: Отправка вопроса и получение посимвольного стриминга ответа.

### Административные методы (Node.js)
- `POST /api/parse`: Запуск процесса парсинга веб-страницы.
- `GET /api/parse-status`: Получение статуса процесса парсинга.
- `POST /api/batch-upload`: Запуск массовой загрузки документов в Qdrant.
- `GET /api/batch-upload-progress`: SSE-эндпоинт для получения прогресса загрузки.
- `GET /api/documents/real-count`: Получение списка и количества PDF-файлов в хранилище.
- `DELETE /api/documents/clear`: Удаление всех локальных PDF-файлов.
- `GET /api/settings` / `POST /api/settings`: Чтение и сохранение конфигурации.

### Методы микросервиса (Python, порт 5001)
- `POST /context`: Поиск релевантного контекста по текстовому запросу.
- `POST /upload`: Загрузка и индексация одного документа.
- `GET /collections`: Получение списка коллекций.
- `GET /collections/<name>/count`: Получение количества векторов в коллекции.
- `DELETE /collections/<name>/clear`: Полная очистка коллекции.
- `GET /health`: Проверка работоспособности сервиса.
